## Counting rule

The relevant category count column (lumber, hardware or other) defaults to `1`. It increments for additional non-overlapping appearances of the same normalized material specification. Overlapping detections from the local rules and AI on the same page are reconciled using the larger supported count, rather than added together. This comparison includes multimodal vision findings. Parenthetical layer counts such as `(2)` do not multiply the item-occurrence count. The count is a drawing occurrence/reference count, not automatically a measured procurement quantity.

## Verification boundary

The regex vocabulary and its sample-term assertions were exercised against the extracted A7.1 text in the development environment. A Windows WPF/.NET build and a complete runtime export against this PDF were not possible here because the .NET SDK/Windows Desktop build tools are unavailable. This coverage note is not a measured bill of materials or a statement that every drawing element has been captured.

## Fast single-pass execution

The current default run path scans the complete extracted page text with the deterministic rules, then makes at most one Ollama model request for that page. With a vision-capable model selected, that single request contains both the rendered page image and a compacted extract of PDF text. The earlier separate text-chunk AI pass and second whole-page vision pass are not used by the default fast path. Results are published to the WPF grid first from deterministic hits and then again after the model response is parsed.
